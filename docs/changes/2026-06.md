## 2026-06-04 13:54 - Reset warm-start checkpoint best loss

**Change size**

**Files changed**

- `tests/test_training_early_stopping.py`
- `docs/current_state.md`
- `docs/known_issues.md`
- `docs/changes/2026-06.md`

**What changed**

- Changed training checkpoint loading so external `resume_model_path` checkpoints are treated as warm starts.
- Preserved the source checkpoint copy in the new run directory, but reset `best_loss` to `inf` for the new run's early stopping and model selection.
- Added a regression test covering external checkpoint warm starts.
- Documented the sweep early-stopping symptom and fix.

**Context**

- Parallel sweep trials resumed from the shared `viplanner/checkpoint` model and inherited its stored best validation loss. If a trial's validation loss did not beat that source loss, early stopping counted every epoch as non-improving even while training loss decreased.

**Impact**

- Warm-start sweep trials now save and compare models using validation loss from the current run.
- True resumes from a run's own `model.pt` still preserve the stored best validation loss.

**What changed**

- Changed `PlannerDataGenerator` to write generated warped semantic images under per-generator `img_warp` subdirectories.
- Changed generated depth-edge images to use per-generator `depth_noise_edges` subdirectories.
- Changed cleanup to remove only the generator-owned generated directories and remove the parent directory only when empty.
- Added tests that verify cleanup does not remove generated directories owned by another active generator.

**Context**

- Parallel sweep runs can share the same dataset environment directories. A finished run could delete the shared `img_warp` directory while another run still had DataLoader samples pointing to files inside it.

**Impact**

- Parallel training sweeps are less likely to fail with missing generated semantic warp files.
- Generated intermediate files remain isolated per generator and are still cleaned up by the owning generator.

## 2026-06-03 18:26 - Sweep max-depth config nesting

**Change size**

- `XS`

**Files changed**

- `viplanner/config/sweep.yaml`
- `docs/build_and_run.md`
- `docs/current_state.md`
- `docs/changes/2026-06.md`

**What changed**

- Changed the sweep grid key from `max_depth` to `data_cfg.max_depth` so generated trial configs place the value inside `TrainCfg.data_cfg`.
- Changed the sweep resume checkpoint path from an absolute workspace path to repository-relative `viplanner/checkpoint`.
- Updated the documented sweep command to reference the existing `viplanner/config/sweep.yaml` file.

**Context**

- Sweep-generated configs passed `max_depth` as a top-level `TrainCfg` field, causing `TypeError: __init__() got an unexpected keyword argument 'max_depth'`.

**Impact**

- Hyperparameter sweep dry-runs and trial configs can load through `TrainCfg.from_yaml` without the top-level `max_depth` error.
- Sweep runs are less dependent on a specific `/workspaces/viplanner` checkout path.

**What changed**

- Replaced reconstruction config `env` usage with validated `env_list`.
- Added single-environment reconstruction config views for per-environment processing.
- Updated depth reconstruction and cost-map build CLIs to process each `env_list` entry separately and stop on first failure.
- Disabled final cost-map visualization by default for multi-environment batches so the command continues after the first environment; added `--final-viz` and `--no-final-viz` CLI controls.
- Updated cost-map root path resolution so `config.general.root_path` is treated as the parent directory containing environments.
- Updated tests, command notes, example config, and documentation for the new config shape.

**Context**

- Reconstruction and cost-map scripts previously handled one environment at a time.
- The requested behavior is to run the same workflow independently for each environment listed in the config.

**Impact**

- Existing configs using `reconstruction.env` now fail with a migration message and must use `reconstruction.env_list`.
- Cost-map configs should set `config.general.root_path` to the parent data directory, or leave it unset/null to derive from `reconstruction.data_dir`.
- Multi-environment cost-map builds save all environments without opening a blocking final Open3D window unless `--final-viz` is provided.
